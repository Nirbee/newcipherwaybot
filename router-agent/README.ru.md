# Агент для роутера CipherWay (этап 6)

Небольшой POSIX-sh скрипт, который работает на роутере клиента (Keenetic + Entware + XKeen) и
поддерживает конфиг Xray в актуальном состоянии. Раз в 5 минут опрашивает
`GET /api/agent/config`, записывает полученный фрагмент outbounds/routing в конфиг-директорию
XKeen, перезапускает Xray только если конфиг реально изменился, и отчитывается обратно через
`POST /api/agent/heartbeat`, чтобы в админ-панели устройство отображалось как «online».

**Автоустановщика пока нет** (это этап 7 — специально отложен до тех пор, пока не сделаем
несколько установок руками и не поймём подводные камни). Ниже — процедура ручной установки.

## Что должно быть на роутере заранее

- Keenetic с уже установленными и рабочими Entware и XKeen (т.е. `xkeen -status` отрабатывает,
  и роутер уже ходит в интернет через Xray каким-то способом — этот агент управляет только
  *outbounds*-конфигом, не самой установкой XKeen).
- `curl` и `jq` из Entware:
  ```bash
  opkg update && opkg install curl jq
  ```

## Установка

1. Скопируйте `agent.sh` на роутер в `/opt/etc/cipherway-agent/agent.sh` и сделайте
   исполняемым:
   ```bash
   chmod +x /opt/etc/cipherway-agent/agent.sh
   ```
2. Скопируйте `agent.conf.example` в `/opt/etc/cipherway-agent/agent.conf`.
3. В админ-панели: **Роутеры → создать** (или **rotate** у уже существующего устройства),
   выберите подписку клиента и скопируйте показанный токен — он показывается один раз.
   Вставьте его в `agent.conf` в поле `TOKEN`.
4. Проверьте, где на *этом конкретном* роутере XKeen хранит свои конфиг-фрагменты — обычно там
   уже лежит несколько файлов вида `NN_*.json`:
   ```bash
   ls /opt/etc/xray/configs/
   ```
   Укажите этот путь в `agent.conf` в поле `CONFDIR` (путь может отличаться в зависимости от
   версии/варианта установки XKeen — мы видели расхождения).
5. Запустите скрипт один раз вручную и посмотрите лог:
   ```bash
   /opt/etc/cipherway-agent/agent.sh
   tail -n 50 /opt/var/log/cipherway-agent.log
   ```
   Ожидается строка вида `config updated -> /opt/etc/xray/configs/10_cipherway.json
   (etag=...), restarting xray`. Убедитесь, что интернет на роутере по-прежнему работает и идёт
   через прокси (в админ-панели статус устройства должен смениться на *online*, появится
   `last_seen_at`, в течение нескольких минут).
6. Добавьте задачу в cron (каждые 5 минут — совпадает с лимитом на сервере):
   ```bash
   echo '*/5 * * * * /opt/etc/cipherway-agent/agent.sh >> /opt/var/log/cipherway-agent.cron.log 2>&1' >> /opt/etc/crontabs/root
   /opt/etc/init.d/S10cron restart
   ```

## Чего скрипт НЕ делает

- Не устанавливает и не настраивает сам XKeen/Xray, не трогает inbounds/DNS/log — подразумевается,
  что это уже настроено и работает на роутере до установки агента.
- Не трогает конфиг, если панель временно недоступна (503) — остаётся последний рабочий конфиг,
  чтобы клиент не терял прокси из-за кратковременного сбоя панели.
- Не удаляет себя сам при отзыве токена — отозванный токен просто будет получать 401/403
  бесконечно; при выводе устройства из эксплуатации нужно вручную убрать строку из cron и
  удалить `/opt/etc/cipherway-agent/`.

## Диагностика проблем

- `tail -f /opt/var/log/cipherway-agent.log` — лог самого агента.
- Получить конфиг вручную, чтобы увидеть, что реально отдаёт сервер:
  ```bash
  curl -s -H "Authorization: Bearer <ТОКЕН>" https://cabinet.cipherway.net.ru/api/agent/config
  ```
- 401/403 в логе — неверный токен или устройство отозвано в админ-панели.
- Конфиг применяется, но интернета нет — скорее всего `CONFDIR`/`OUTFILE` указывают не туда,
  откуда реально читает XKeen, либо не сработала команда перезапуска; после ручного запуска
  проверьте `xkeen -status`.
